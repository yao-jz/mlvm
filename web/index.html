Verifiable model execution

Verify how a model
produced its answer.

A model answer alone does not show how it was produced. MLVM runs the compiled model inside a RISC-V virtual machine. The VM executes RISC-V instructions in software, reads model files from its in-memory file system, and handles supported Linux system calls such as opening a file. Another computer can repeat the run and compare a hash of the VM's registers, memory and files, even when the displayed words match. If the runs disagree, a checker can find and re-execute the disputed RISC-V instruction.

Independent checks

The checker can use a different computer.

One person can run the RISC-V program inside MLVM on a Mac; another can repeat it on Linux, Windows or in a browser. The same virtual machine and staged inputs produced matching runs for the built-in story model.

See the cross-computer test →
  • Run a RISC-V model programMLVM executes compiled RISC-V instructions in software, including floating-point math. The host needs no RISC-V processor.
  • Control OS calls and filesThe VM answers supported Linux system calls and serves model files from its in-memory file system.
  • Repeat it across hardwareThe same TinyStories program and inputs produced matching VM hashes on Mac, Linux, Windows and WebAssembly.
  • Check one RISC-V instructionWhen two final hashes differ, compare VM states during the runs and re-execute a disputed instruction from saved values.

Try it · Part 2 of 2

What if two runs disagree?

MLVM runs the same RISC-V program again, but deliberately changes the result of one instruction. You can choose other mistakes below. The two runs may print the same words while holding different numbers inside.

If their final hashes differ, MLVM narrows the disagreement to one RISC-V instruction and checks what it should have done. The default example takes about 26 hash comparisons to find one instruction among 38 million.

Try the default first. It makes a tiny change to one floating-point instruction's result. Later instructions can erase the change, so MLVM tries another place until the finished runs differ.

    How the check works

    Find the difference. Check the instruction.

    A compiled model runs as RISC-V instructions: multiply numbers, read memory, take a branch. MLVM executes them inside its virtual machine. Its in-memory file system supplies staged inputs, and the VM answers supported Linux system calls without booting Linux. A hash summarizes the VM state after any instruction.

    1. 1

      Fix the program and its inputs

      Both runs use the same RISC-V executable, model weights and prompt. Input files are staged in the VM before execution, so the program reads the same bytes on either computer.

    2. 2

      Compare VM state halfway through

      Ask each run for its hash after the same number of instructions. Keep halving the range where the hashes differ until one RISC-V instruction remains.

    3. 3

      Re-execute that instruction

      Using the saved VM state and memory values from just before it ran, a separate checker determines the instruction's correct result without rerunning the model.

    The same words can hide a wrong instruction result.

    We changed the result of one RISC-V floating-point multiplication during a SmolLM2 language-model run. It printed the same text, but held a different number inside.
