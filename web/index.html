A research demo for checking model runs

Two model runs disagree.
Find the step where they split.

Suppose someone runs a model for you. The answer alone cannot show how they got it. MLVM runs the model in a virtual machine that can capture its state at any instruction. Someone else can run the same program. If the two runs start alike but end differently, MLVM narrows the disagreement to one instruction and checks that step locally.

Try it in your browser ↓ See how it works

Research prototype. The demo runs locally in your browser. Disputes run locally today; an on-chain dispute system is not built yet. What it can and cannot verify →

  • A RISC-V virtual machineModels compile to RV64IMAFD and run in software, floating point included. No GPU or RISC-V hardware needed.
  • Deterministic across platformsThe same program and inputs give bit-identical states. CI checks Linux, macOS, Windows and WebAssembly.
  • Verifiable, one instruction at a timeAny machine state has a 32-byte fingerprint. One instruction can be rechecked from a few kilobytes.
  • DisputableWhen two runs end differently, about log₂ N rounds find the step where they split: 34 for 14.8 billion.

The idea in three steps

Compare two runs.
Check one step.

An instruction is one small operation, such as adding two numbers or reading memory. MLVM gives the same program and inputs the same rules on different computers. It can summarize the virtual machine's state with a short fingerprint after any instruction.

  1. 1

    Summarize the state

    A 32-byte fingerprint represents the machine's memory, registers and tracked files after any instruction. The model's stored answer is included.

  2. 2

    Find a step where they split

    If two runs start alike but finish differently, compare their fingerprints halfway through. Repeat in the half where they differ until one instruction remains.

  3. 3

    Check that instruction

    A local referee checks the disputed instruction using a saved state and proof of the memory it used. It does not need to rerun the model. This demo supports selected steps; a complete dispute system is still future work.

Try it · Step 2 of 2

Change one result.
Locate the changed step.

A second copy runs the same program but changes one result, as a faulty machine might. The story may look the same even when the machine's final fingerprint differs.

The search compares the two machine states halfway through the run, then repeats in the half where they first differ. For the default prompt, about 26 rounds narrow 38 million instructions to one. The local referee checks that step.

Try the default first. It makes one number slightly wrong. If later calculations erase the change, the demo tries another location until a difference survives.

      On your own machine

      Explore MLVM on your machine.

      The command-line tool runs the same virtual machine on Linux, macOS and Windows. Try the built-in model, or run a local dispute with your own compiled RISC-V program.

      1. Install MLVM

      brew install yao-jz/tap/mlvm
      Linux, Windows or building from source

      For Linux and macOS:

      curl -fsSL https://raw.githubusercontent.com/yao-jz/mlvm/main/install.sh | sh

      or from source, with Go 1.23+

      git clone https://github.com/yao-jz/mlvm && cd mlvm && make build

      On Windows, download the zip from GitHub Releases. See the installation guide for details.

      2. Run a model and test a disagreement

      # Run the model and print its final fingerprint
mlvm demo "Once upon a time"

# Deliberately change one result and find the step
mlvm liar

# Count instructions by function
mlvm xray --svg flame.svg
      Save the evidence, or use your own program 
      # Save the evidence, then verify it independently
mlvm liar --lie token --word Tim --json > dispute.json
mlvm referee dispute.json

# Use a statically linked RV64IMAFD executable
mlvm xray --elf ./your-program
mlvm liar --elf ./your-program

      The native CLI also runs the integer verdict through RISCV.sol's compiled bytecode in an in-process EVM.
