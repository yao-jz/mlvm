Verifiable model execution

Verify a model’s computation,
one instruction at a time.

Someone runs a model for you and returns an answer. The answer alone cannot show that they ran the computation you agreed on, and running it again yourself is expensive. MLVM makes every instruction of the run checkable, so any disagreement comes down to a single instruction that anyone can verify.

How verification works

Fingerprint every step.
Check only the one that differs.

MLVM runs the model’s compiled program in a RISC-V virtual machine where every instruction, floating point included, has exactly one correct result. That makes the whole run checkable, one instruction at a time.

  1. 1

    Fingerprint every step

    The machine’s state after any instruction, memory, registers and files included, hashes to one 32-byte fingerprint. The same program and inputs give the same fingerprints on any computer.

  2. 2

    Find the first disagreement

    If two runs end with different fingerprints, compare them halfway through, keep the half where they first differ, and repeat. About log₂ N rounds leave one instruction: 26 for this page’s 38 million, 34 for 14.8 billion.

  3. 3

    Check that one instruction

    A referee re-executes only that instruction, from a 674-byte record of the machine’s state and proofs of the memory it touches. It never runs the model.

Why a RISC-V virtual machine?

A referee needs an exact rule for the step it checks. RISC-V gives us a common instruction set: additions, memory reads and other small operations with defined behavior. C and Rust programs can compile to that target, so the same machine can run different models and their surrounding code.

The program runs inside MLVM. You do not need a RISC-V processor. More on this choice →

Floating point belongs in the VM, too.

Models do much of their work with floating-point numbers. MLVM uses Berkeley SoftFloat to compute those operations in software, including rounding and exception flags. That gives different hosts the same arithmetic rules, down to the bits, so a referee can tell a wrong result from a different rounding.

    Try it · Step 2 of 3

    Change one instruction.
    Watch it get caught.

    A second machine runs the same program but changes the result of one instruction, as a faulty or dishonest machine might. Its story often looks the same. Its fingerprint does not.

    The search asks both machines for their fingerprint halfway through, keeps the half where they first differ, and repeats. About 26 rounds narrow 38 million instructions to one, and a referee checks that instruction on its own.

    Try the default first. It makes one number slightly wrong. If later calculations erase the change, the demo tries another location until a difference survives.

      On your own machine

      Verify on your own machine.

      The command-line tool runs the same VM natively on Linux, macOS and Windows. Start with the built-in model, then verify your own compiled RISC-V program.

      1. Install MLVM

      brew install yao-jz/tap/mlvm
      Linux, Windows or building from source

      For Linux and macOS:

      curl -fsSL https://raw.githubusercontent.com/yao-jz/mlvm/main/install.sh | sh

      or from source, with Go 1.23+

      git clone https://github.com/yao-jz/mlvm && cd mlvm && make build

      On Windows, download the zip from GitHub Releases. See the installation guide for details.

      2. Run, verify and profile

      # Run and commit: prints the final fingerprint
mlvm demo "Once upon a time"

# Change one instruction and catch it
mlvm liar

# Count every instruction, by function
mlvm xray --svg flame.svg
      Save the evidence, or use your own program 
      # Save the evidence, then verify it independently
mlvm liar --lie token --word Tim --json > dispute.json
mlvm referee dispute.json

# Use a statically linked RV64IMAFD executable
mlvm xray --elf ./your-program
mlvm liar --elf ./your-program

      The native CLI also runs the integer verdict through RISCV.sol's compiled bytecode in an in-process EVM.

      MLVM is MIT licensed and derived from Asterisc; floating point is a Go port of Berkeley SoftFloat 3e; the model is karpathy/llama2.c's TinyStories-260K (MIT).
